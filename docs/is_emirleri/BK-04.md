## Kapılar

Her kapının çıktısı Mac'te `~/Desktop/Claude Portman Çalışması/29_BK04/` altına `bk04_<n>_<ad>.txt` olarak kaydedilir ve içinde anahtar değeri yoktur (betikler yazmaz). Çıktı Claude'a verilince belgeye kanıt olarak işlenir.

### Kapı 1 · Ön denetim (salt okunur; değişiklik yok)
```
scp vps/anthropic_anahtar.py portman-vps:/root/
ssh portman-vps 'bash -s' < vps/bk04_on_denetim.sh > bk04_1_on_denetim.txt 2>&1
```
`bk04_on_denetim.sh` (yeni): servis, agent.env'deki anahtarın parmak izi ve Anthropic'te geçerliliği (GET /v1/models, ücretsiz), SSH'nin **etkin** ayarları (`sshd -T`), drop-in dosyaları, root'un yetkili anahtar sayısı, 7 günlük başarısız parola denemesi sayısı, ufw ve fail2ban durumu. IP, kullanıcı adı ve anahtar içeriği yazılmaz.

Durma koşulu: yetkili anahtar yoksa kapı 6 yapılmaz (önce `ssh-copy-id`).

### Kapı 2 · Yeni anahtar (Console; Lokman)
Claude Console → API Keys → yeni anahtar (ad önerisi `portman-2026-10`; son kullanma tarihi verilecekse en az 6 ay). Anahtar panoya kopyalanır; ekranda açık bırakılmaz; **eski anahtar henüz iptal edilmez**. Console'daki son 4 karakter not edilir (kâğıda; parmak izi karşılaştırması için).

### Kapı 3 · VPS'e yerleştirme ve öz-test (ücretli: 1 LLM çağrısı ≈ 0,03 $; onaylı)
```
pbpaste | ssh portman-vps 'python3 /root/anthropic_anahtar.py' > bk04_3_vps_anahtar.txt 2>&1
pbcopy < /dev/null
ssh portman-vps 'bash -s' < vps/oz_test_yenile.sh > bk04_3_oz_test.txt 2>&1
```
`anthropic_anahtar.py` (İE-02 kapı E, var olan betik): anahtarı standart girdiden alır, `agent.env`'e yazar, izni/sahibi korur, anahtarsız yedek alır, GET /v1/models ile sınar; servisi yeniden başlatmaz. `oz_test_yenile.sh` (var olan): servisi yeniden başlatır, öz-testi koşturur; WhatsApp'a göndermez. Beklenen: `durum passed`, LLM `anthropic claude-opus-5-5`, yeni parmak izi kapı 1'dekinden farklı.

Durma koşulu: öz-test geçmezse hosting'e dokunulmaz; eski anahtar hâlâ geçerli olduğu için canlı akış durmaz. `agent.env`'in anahtarsız yedeği durur; eski anahtar satırı geri yazılmaz (ilke), yeni bir anahtar üretilir.

### Kapı 4 · Hosting'e yerleştirme (DirectAdmin; Lokman)
DirectAdmin → File Manager → `/home/portatifevcom/portman_app/claude_api.json` → düzenle → `"api_key"` değerini panodaki yeni anahtarla değiştir → kaydet → dosya izni 600 kalsın → panoyu temizle. Dosyayı yeniden açıp son 4 karakteri kapı 2'deki notla karşılaştır.

Hosting tarafı için ücretsiz doğrulama yolu yok (sahte test `hosting/tests/claude_api_test.php` ağa çıkmaz). Doğrulama: aynı değer VPS'te HTTP 200 aldı (kapı 3) + son 4 karakter aynı. İstenirse Patron numarasından bayi botuna tek bir sohbet mesajı atılır (ücretli: 1 LLM + 1 WhatsApp; ayrı onay) ve panelin sohbet kaydında cevap görülür.

### Kapı 5 · Eski anahtarın iptali (Console; Lokman) ve günlük denetimi
Console'da eski anahtar **Revoke**. Sonra:
```
ssh portman-vps 'PM_BASLANGIC="<kapı 3 tarihi saat>" bash -s' < vps/gunluk_api_hatalari.sh > bk04_5_gunluk.txt 2>&1
```
Beklenen: iptalden sonra günlükte 401/`authentication_error` yok; servis kapı 3'teki PID ile çalışıyor. Bayi botu için: iptalden sonraki ilk gerçek bot cevabı panel kaydında görülür (bekleme; ücret doğurmaz).

### Kapı 6 · SSH parolalı girişin kapatılması (değişiklik; ayrı onay)
Ön koşul (Mac, 1. terminal; **bu oturum açık kalır**):
```
ssh -o PasswordAuthentication=no -o PreferredAuthentications=publickey portman-vps
```
Girdi "anahtarla" olmalı. 2. terminalde:
```
ssh portman-vps 'PM_ONAY=evet bash -s' < vps/bk04_ssh_sertlestir.sh > bk04_6_ssh.txt 2>&1
```
`bk04_ssh_sertlestir.sh` (yeni): `/etc/ssh/sshd_config.d/00-portman-bk04.conf` yazar (`PasswordAuthentication no`, `KbdInteractiveAuthentication no`, `PermitRootLogin prohibit-password`, `PubkeyAuthentication yes`), `sshd -t` ile sözdizimini, `sshd -T` ile etkin değeri denetler, `systemctl reload ssh` yapar (açık oturumlar kopmaz). `PM_ONAY=evet` verilmemişse, yetkili anahtar yoksa, sözdizimi geçmezse ya da etkin değer hâlâ `yes` ise dosyayı geri alır ve DUR der.

Neden `00-` adı: Ubuntu 24.04'te `sshd_config` drop-in'leri ad sırasıyla okur ve **ilk gördüğü değeri** kullanır; Natro imajındaki `50-cloud-init.conf` `PasswordAuthentication yes` içerebilir. `00-` dosyası ondan önce okunur.

Sonra, 2. terminalde iki deneme:
```
ssh -o PasswordAuthentication=no -o PreferredAuthentications=publickey portman-vps 'echo anahtar-ok'      # anahtar-ok
ssh -o PubkeyAuthentication=no -o PreferredAuthentications=password portman-vps                            # Permission denied (publickey)
```
Geri alma (1. terminaldeki açık oturumdan): `rm /etc/ssh/sshd_config.d/00-portman-bk04.conf && systemctl reload ssh`. Son çare: Natro panelindeki konsol (VNC).

ufw'ye dokunulmaz; kuralları kapı 1'de okunur ve DURUM'a "okundu" diye işlenir. Değişiklik gerekiyorsa ayrı iş.
